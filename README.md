# AudioMixer PoC

Swift / SwiftUI製のmacOSメニューバー音量ミキサー。macOS 15以降、追加ライブラリ・仮想オーディオドライバー不要。

## 起動

```sh
./build.sh --open
```

ビルド済みアプリは `build/AudioMixer.app`。メニューバーのスライダーアイコンをクリックしてください。Dockには表示しません。

起動時にTapのみのデバイスで読み取りを開始し、macOSへ音声収録の許可を自動で要求します。要求ボタンを押す必要はありません。未許可なら標準ダイアログで許可してください。許可済みなら標準ダイアログは通常再表示されません。拒否済みでダイアログが出ない場合は「音声収録の許可設定…」からシステム設定を開いてください。許可要求用の音声は再生・保存せず破棄します。

- メニューバーのアイコンからAppKitの標準`NSMenu`を開きます。
- 起動時から音声出力中のアプリを自動で管理し、新しく音声を出すアプリも2秒間隔で追加します。
- アプリごとのmacOS標準スライダーをドラッグして音量を調整します。左端が0%、目印が100%、右端が設定したBoost上限です。100%を超えてドラッグを離した時に、ポップアップ内へ対象アプリ名・変更先の音量・聴覚への負担や音割れに関する注意を表示します。「Boostを有効にする」を押すまで音量は上げません。別ダイアログは開きません。Boost中はアイコンにBoostバッジを表示し、リッチモードでは音量値にもBoostを併記します。100%以下に戻した後、再び超える際は再表示します。背景・区切り線・「設定…」のメニュー項目は実際のNSMenu / NSMenuItemを使用し、アクセントカラーとライト／ダークの設定に従います。macOSで「透明度を下げる」が有効なら、その設定を尊重します。
- 音声ボタンは現在の状態を「音声オン／ミュート中」とスピーカー／消音アイコンで表示します。クリックで切り替えます。管理は自動で行います。
- 設定画面の「すべて停止」で元の音声出力へ戻し、自動管理も停止します。「アプリを自動で管理」で再開できます。
- メインのポップアップは音量一覧と標準のNSMenuItemによる「設定…」だけです（⌘,に対応）。自動管理・音声収録の許可設定・全停止・終了は別の設定ウィンドウへ移しています。

システムの出力先に自動追従します。出力先変更を2秒間隔で検出し、Tapをミュート状態で保持したまま出力だけ再構築します。再生開始はgain 0から設定音量へ立ち上げます。システム全体の出力先は変更しません。

## 実装

アプリのCore Audio process IDs → stereo Process Tap (`.muted`) → private Aggregate Deviceの入力 → HAL IO callbackでFloat32 PCMにgain乗算 → 指定した出力デバイス。

出力デバイスのUIDはAggregate Deviceの出力側に指定しています。Tapの`deviceUID`で再生先を指定しているわけではありません。物理出力デバイスを含むprivate Aggregate Deviceをアプリ内部で作成し、停止時に破棄します。出力デバイスの物理入力ストリームはIOProcで無効化します。リアルタイム処理にロック、メモリー確保、ログ出力はありません。スライダー変更は1コールバック分のgain rampで反映します。

## PoCの範囲

- 一覧は起動中のアプリです。無音のアプリも表示します。通常の起動中アプリに加え、音声を出しているバックグラウンドアプリを表示します。Helperプロセスは実行ファイルが属する最外側の.appから親アプリ名を取得してまとめます。親アプリを特定できないプロセスのみbundle IDやPIDで表示します。
- 同じ親アプリのプロセスをまとめます。再生停止やアプリ終了で音声プロセスが消えた場合は調整を解除します。新しい音声プロセスは自動管理中なら追加します。
- Float32 PCM、出力の先頭2チャンネルに対応。出力デバイスが対応していれば、デバイスのサンプルレートをTapと同じ値に自動設定します（例 96kHz→48kHz）。アプリ内の再サンプリングは行いません。非対応のレートなら開始を中止します。最後の管理対象を停止した時や終了時に元のレートへ戻します。デバイス側の設定変更は同じ出力先を使う他アプリにも影響します。音源やCore Audio Tapでの取得まで含めた無劣化を保証する実装ではありません。非対応フォーマットは開始前にエラーにします。出力再構築中のエラーは元音の急な再生を防ぐためTapのミュートを維持します。設定画面の「すべて停止」でTapを破棄して解除します。サラウンドは未実装です。アプリごとの音量は親アプリのbundle IDをキーに保存します。
- 出力変更時は再構築による短い途切れがあります。AirPods切替、長時間の音切れ、複数アプリの合算クリッピング、実測遅延は実機検証が必要です。
- 複数アプリは個別のTap/aggregate/callbackを使います。gainの上限は設定画面で100〜1000%に変更できます（初期値200%）。300%などを直接入力でき、保存します。Boost時は大きなピークを±1に制限するため、元音が大きい場合は歪むことがあります。
- プロセス復元や新規Helperを即座に捕捉する製品用の仕組みはありません。

## 検証

```sh
./build.sh
build/AudioMixer.app/Contents/MacOS/AudioMixer --self-test
build/AudioMixer.app/Contents/MacOS/AudioMixer --list
```

`--self-test`は実際のrender関数へステレオPCMを渡し、gain ramp・0%・チャンネル配置をassertで検証します。`--list`は実機の音声プロセスと出力先を読み取ります。ビルドとこれらのチェックは音声収録許可や実際の再生品質の検証とは別です。

許可要求は起動時の読み取り1か所にまとめています。この読み取りで実際の非ゼロPCMを受け取るまでアプリ別Tapは待機します（無音なら待機します）。許可済みとの未確認の推定や非公開TCC APIは使いません。許可前に複数アプリ分の要求が同時に走るのを防ぎます。ローカルのadhoc署名ビルドは、更新後にmacOSが再許可を求めることがあります。

設定画面の「表示モード」でリッチ／コンパクトを選べます。リッチはアプリ名・音量値・ミュート状態を表示します。コンパクトはアイコン・スライダー・ミュートボタンを横一列に並べます。アイコンや操作へポインタを合わせるとアプリ名・音量・現在のミュート状態を確認できます。表示モードは保存します。

Boostの承認待ち音量はスライダー表示として保持し、実際のgainには承認まで適用しません。ドラッグ中に確認欄が現れてバーの位置が動くことを防ぎます。`--self-test`でドラッグ中の保留・リリース後の要求保持を検証します。

Boostの上限を下げると、保存音量・実際のgain・承認待ちの音量を新しい上限まで下げます。上限を上げただけでは現在の音量は変えません。

## 一括制御

設定画面の「一括制御」で対象アプリへチェックを入れ、音量を指定して「音量を適用」を押します。「全選択」「選択解除」、選択アプリの「ミュート」「アンミュート」も使えます。

通常の適用では、選択アプリを指定した音量へ揃えます。「音量を下げるだけ」をオンにした時は、指定音量よりすでに小さいアプリを維持します。音量変更だけではミュートを解除しません。あるアプリ以外を下げたい場合は全選択して、そのアプリだけチェックを外してください。操作は適用時点の起動中アプリが対象です。
